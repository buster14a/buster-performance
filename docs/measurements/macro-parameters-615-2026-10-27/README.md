# Macro parameter indexing, #615 — 2026-10-27

Qualification for [Buster PR #631](https://github.com/buster14a/buster/pull/631),
addressing [issue #615](https://github.com/buster14a/buster/issues/615).

The temporary index removes the measured quadratic growth in validation and first replacement compilation. At 4,000 parameters, median wall time falls 5.399 → 0.980 ms when invoked and 3.613 → 0.691 ms when unused. All 7,722 measured processes exit zero. Ordinary controls remain close in wall time; the amplified four-parameter control retains a +1.60% user-cycle cost, reported below.

## Measurement method

Every target build, test and measurement takes `exclusive.sh` separately.
Timings are pinned to CPU 2, using the performance governor. No lock is held
across rounds. Exact commands are in [commands.txt](commands.txt).

Both source trees are built with six placements of `main_unit_frontend.c`:
0, 704, 1,408, 2,112, 2,816 and 3,520 bytes of padding, spread over a page.
The unit requires 64-byte alignment. Build logs, executable hashes and the
`pp_define` symbol addresses verify these placements. The baseline placement
set is reused unchanged across the last three candidates.

`time-runs` interleaves `base`, `head` and `base-again` (the baseline a
second time), in rotating order. Each placement runs from three fresh physical
executable copies with equal-length paths, so stack offsets match. Each round
discards its warmups. Three rounds of three samples per placement/copy give
162 samples per build/input. A timed process includes startup, all compiler
work, output and teardown; counters cover all its threads from exec.
Every accepted measured process exits zero with counters present.

The native harness reports each round's per-placement/copy medians and
pairwise ranges. The second baseline label provides an A/A floor. Differences
between builds are interpreted against both floors; shifts are not paired
between trees as if their code occupied the same addresses.

Primary `placements-v6-*.log` list order:

| List | Input / command |
| --- | --- |
| 1–3 | `-E -P inputs/macro-{1000,2000,4000}.c -o /dev/null` |
| 4–6 | `-E -P inputs/macro_unused-{1000,2000,4000}.c -o /dev/null` |
| 7–10 | `-E -P small-inputs/small-{0,1,2,4}.c -o /dev/null` |

The after-scalar campaign stays separate: before every measured child,
100 ms of scalar work runs on that CPU. Three rounds of one sample per
placement from two fresh copies give 36 samples per label/input. Its four
lists are invoked 4,000, unused 4,000, SQLite `-E -P`, and 10,000 four-parameter
macros. Logs are `conditioned-placements-v6-*.log`.

`summarize.c` rejects failed processes, missing counters, malformed process
lines and trailing failure markers. It aggregates every accepted sample with
the project's upper median for even counts. Wall ranges include all samples;
no observation is removed for its timing. Wall precision is the harness's
0.001 ms. RSS is the median of per-process peak RSS, in KB. Reader controls
check original/placement formats, status failure, missing counters and
malformed/trailing content; archived earlier summaries reproduce exactly.

Two initial setup attempts preceded the first candidate build and failed to
find its executable; they produced no timing samples. Initial placement builds
used 688-byte offsets from the checker's example and correctly refused the
frontend's 64-byte alignment. Their failed setup logs are retained separately
from accepted campaigns.

At 4,000 parameters, invoked macros use 94.85% fewer instructions and improve 5.51× by median wall time; unused macros use 97.93% fewer instructions and improve 5.23×. Second-baseline medians are 5.383 and 3.609 ms.

Invoked instructions grow 2.66 → 4.56 → 8.32 million at N = 1,000/2,000/4,000; unused instructions grow 1.18 → 1.59 → 2.40 million. The original controls grew approximately fourfold when N doubled. Residual work grows roughly linearly after fixed startup costs; invocation minus unused instructions also approximately doubles. These observations support removing both quadratic costs on the measured inputs.

RSS is reported as observed, without inferring memory savings from small differences between executables and placements.

## Correctness and scope

Local AMD Ryzen 9 7940HS / Clang 23.1.4 and locked native release builds,
complete preprocessor/Clang suites (`--fuzz 1500 --seed 615`, 4 local / 8
native jobs), and call-graph checks pass for this source. The suite includes
377 fixtures, 2,186 predefine option sets and 3,000 generated C17/C23 cases,
with zero kernel/oracle differences and zero unverified cases. The call graph
has 41 units, 23,993 functions, zero unapproved cycles, three existing allowed
cycles and zero split variables. Frozen SQLite matches 706,237 Clang tokens.

Focused ASan+UBSan checks pass with leak detection enabled. They cover
scalar/vector lookup, guarded 0–16-name views, sparse ids and misses, first
ordinals, failed descriptor/table allocation and partial-construction rollback,
ordered diagnostics, 4,096-parameter boundaries, repeated expansions, `#`,
`##`, standard/GNU variadics, `__VA_OPT__` and explicit `__VA_ARGS__`.
The source count stays 32-bit until its limit is checked, including the
65,536-name invalid-list regression. Matching logs are retained.

`focused.c` and `focused_lexer.c` provide the focused entry points. Their
build/run command, full native tests and readers are recorded in
[commands.txt](commands.txt).

Implementation, tests, readers and focused wrappers are original project work
under Apache-2.0 WITH LLVM-exception. The retained generator has the same
project terms. Included Buster modules keep their recorded component terms.
Clang is an external oracle; no external implementation is imported.

These synthetic inputs establish the changed scaling mechanism, not the
frequency of large macros in real programs, an absolute throughput ceiling,
or a broad whole-compiler speedup. Hash lookup has expected constant cost,
not a worst-case collision-free guarantee. At the valid 4,096-name limit,
geometric table allocations total 130,560 bytes, plus the descriptor and
alignment, under 128 KiB of payload for this index. Temporary index lifetime does
not imply immediate decommit of arena pages; the RSS results remain the
process-level memory observation. Acceptance here covers this module and
these recorded inputs. It does not stand in for the required whole-compiler CI.
