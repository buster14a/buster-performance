Diagnostic setup adapters
Original first-party C instrumentation, stored as setup-base.patch and setup-fixed.patch under tools/. Patches apply only to c_check_intrinsic_input.c in isolated copies of buster source e693d878309ed3c3be05f2f550574d59217deceb and 60429e6479ee5f9ccbfb790dc86581a36c1279d2. They add a time.h include, timestamp entry/exit of the actual check_input_intrinsic_initialize body with CLOCK_MONOTONIC, abort on clock failure/backward values/duration overflow, and print intrinsic_setup_ns=N to stderr after the ending timestamp. No production source branch is changed by these patches.

The interval includes the actual initializer's source operand scan, cache deduplication and construction, batched lookup, second call-count scan when needed, intrinsic table allocation/initialization and rollback. It excludes subsequent check_input_intrinsic_prepare/type decoding/call conversion and all later compiler stages. Values are elapsed monotonic nanoseconds, not CPU cycles or CPU-only time. Clock-call overhead is not subtracted. stderr output occurs outside its own interval but can disturb following work. Instrumentation changes code generation, instruction layout and register allocation, so these diagnostic binaries do not replace unmodified shipping whole-compile timings or the separately proved placement campaign.

Only checker object 8 is rebuilt with the recorded exact original Clang 23.1.4 -O3 -march=znver5/no-debug flags. All other 40 retained objects for that revision remain byte-identical. Objects are relinked in numeric 0..40 order with clang -no-pie -fuse-ld=wild ... -lm -ldl. Source directories remain work/pr914-setup-{base,fixed}; output binaries remain work/pr914-evidence/setup-{base,fixed}, outside Git. Exact source patches, commands and binary hashes are retained here.

Original C runner
setup_runner.c forks/executes both diagnostic compilers in rotating per-round order; redirects child stdout to /dev/null; drains and caps retained stderr at 4 MiB; parses every exact intrinsic_setup_ns decimal line; rejects no-row, malformed/unterminated/displaced marker, uint64 parse/sum overflow, capture overflow, pipe/child failure and unexpected row counts. It does not measure whole-process time. Command: setup_runner BASE FIXED ROUNDS EXPECTED_ROWS -- COMPILER_ARGS... . Pass EXPECTED_ROWS=1 for each successful single-translation-unit SQLite/tiny invocation; the same explicit count is required in every base/fixed round. A generic multiple-row sum remains available only when its exact expected count is explicitly supplied.
