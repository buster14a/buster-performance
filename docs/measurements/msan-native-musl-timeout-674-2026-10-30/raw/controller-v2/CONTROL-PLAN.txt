Private C controller controls: PREPARED ONLY, not compiled or executed.

After independent review, compile containment-fixture.c using the separately
verified official compiler and ordinary C17 -O2 -Wall -Wextra -Werror. Preserve
the compiler/source/binary identities, argv, output and compile exit. Do not
build or invoke Buster for these controls. Each control gets a fresh receipt
directory and the existing cores budget. Keep the controller's whole external
deadline longer than its command deadline plus cleanup/finalization budgets.

Controller interface supplied by the owning implementation task:
  diagnostic-controller control SECONDS RECEIPT_DIR COMMAND [ARGS...]

Prepared meaningful cases (use the compiled fixture's absolute path):
  control 2 NEW_EXIT7_DIR FIXTURE exit7
    Original command result must remain 7; cleanup must prove ECHILD. A
    controller acceptance result of failure must not overwrite that result.
  control 2 NEW_ESCAPE_DIR FIXTURE escape
    Original result must be the controller's timeout status 124. The command
    log must contain session_child, separate_group_grandchild and the
    ready_parent_wait line. The session child has sid=pid; the grandchild has
    pgid=pid in that session. Thus group-only cleanup cannot satisfy this case.
    Cleanup must record killing/reaping owned descendants until ECHILD.
  control 2 NEW_ORPHAN_DIR FIXTURE exit-with-escape
    Original result must remain 7, with both escaped descendants proven ready
    before the parent's ready_parent_exit7 line. Cleanup must adopt, kill and
    reap the surviving descendants and prove ECHILD even after the command
    process has already exited.
  control 2 NEW_SIGNAL_DIR FIXTURE signal
    Original result must remain 143 (128 + SIGTERM), with a wait/si_code that
    identifies signal death rather than an ordinary exit143; cleanup ECHILD.
  control 2 NEW_EXEC_FAILURE_DIR /definitely/nonexistent/controller-fixture
    Preserve exec failure127, cleanup ECHILD, and an execution failure receipt.
    The command log must name launch_failure stage=execv and its errno.
  control 2 NEW_NORMAL_EXIT127_DIR FIXTURE exit127
    Preserve normal exit127 and cleanup ECHILD. The fixture's direct_exit127
    identity must be present and the exec-failure marker absent, distinguishing
    this successfully launched program from the nonexistent executable.
  control-postfail 2 NEW_POSTFAIL_DIR FIXTURE exit7
    The real sha256sum postcheck of a deliberately absent private manifest
    must fail. Original command7 and raw exit status remain visible, cleanup
    is ECHILD, and finalstatus7 preserves the original nonzero command while
    the separate postcheckfailure remains recorded.
  control-postfail 2 NEW_POSTFAIL_ZERO_DIR /bin/true
    Original command0 remains visible, cleanup is ECHILD, the actual absent-
    manifest postcheck fails, and finalstatus1 prevents a false successful run.

Check every control's always-written final status and original-result receipt,
not just its top-level exit. Successful containment requires ECHILD and no
matching logged process identity surviving in /proc. PID-only absence checks
are supplementary: process IDs can be reused, so ECHILD from the subreaper is
the containment proof. An incomplete-cleanup case is fatal/provisional and
cannot be accepted merely because a command returned the expected status.

No fixture calls exec, ptrace, GDB, a compiler, Buster, the oracle or a corpus.
The separate-session controls intentionally omit descendant PDEATHSIG so they
exercise adoption and cleanup rather than disappearing with their parent.
All ready lines are emitted after a one-byte pipe handshake; descendants are
already created, placed and logged before a parent can exit or wait forever.
The fixture needs Linux/POSIX fork, setsid, setpgid and SIGTERM. These controls
do not establish sanitizer detection, source identity or corpus acceptance.
