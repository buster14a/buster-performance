## Subsequent dispatch-relay finding

The measured strict control guard requires unchanged split flags and guards
SUCCESSOR placement changes when the immediate target terminates in an
indirect branch. That condition does not cover all of the emitter's dispatch
copying behavior.

The dispatch pass can copy an indirect jump into an earlier single-successor
relay, then copy that relay's new first record into a later jump. A guard that
checks only the immediate IR terminator misses such relay chains. Separately,
inserting or removing PREDECESSOR moves in a one-successor relay can change
whether its first record is an indirect-jump copy, and therefore whether a
later incoming jump fuses. That change can alter a branch instruction count
without changing any split flag.

The separate [branch-cost support record](branch-cost-support.md) contains a
focused C harness using the actual extracted emitter functions. It reproduces
these cases and tests conservative chain and predecessor-presence refusals,
alongside a per-edge conditional-branch pricing helper. **That helper and its
guards were not in the measured batch-v2 candidate.** The finding limits the
generic path certificate; it does not alter the captured counts or establish
that either measured workload experienced this unmodeled change.
