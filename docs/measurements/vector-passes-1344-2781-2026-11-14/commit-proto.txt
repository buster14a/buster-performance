Prototype: LICM and value numbering on vector and mask values only (#1344)

Measurement prototype, not for merge as is. With BUSTER_PROTO_VECTORS set
in the environment, --tier1-passes=+licm,+gvn act only on values of vector
or mask type: LICM moves the available candidates of those types and the
in-loop operands they need, and value numbering applies a congruence only
to them. Without the variable the objects are byte-identical to main's.

On the vector lexer (c_tokenize, mid200.c, the owner's Zen 4 desktop, nine
interleaved rounds): default 10.31 cycles/B, +licm,+gvn 5.75, this 5.38,
clang -O2 1.19; 31 hoisted and 4,172 merged values against 1,886 and
57,071, and 4,946 / 5,951 spill stores and loads against 8,203 / 9,275.
Numbers and method are in #1344's comments.
