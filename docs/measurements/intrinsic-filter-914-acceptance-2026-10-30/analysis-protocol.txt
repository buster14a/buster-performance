Offline cycle-attribution reproduction and scope

Original analysis code in tools/ was authored for this packet under its stated
Apache-2.0 WITH LLVM-exception license. No upstream perf implementation source,
modified compiler ELF, external runtime ELF or inherited-environment capture is
included in this repository. The exact measured compiler binaries and six
eligible raw perf captures are separate release assets.

The actual recorded offline commands retain their original absolute workspace
paths. To reproduce elsewhere, mirror the directory structure or adjust only the
workspace/campaign/tool variables in the shell entry points, recording that
change and the resulting tool identities. Obtain the runtime ELF files matching
the recorded package, SHA-256 and build IDs before decoding. Analysis does not
execute those runtime ELF files or the measured compiler. perf, libdw and libelf
must support the recorded x86-64 DWARF format. Decoder versions and hashes are in
analysis/final-perf-build-options.txt and final-decoder-sha256.txt.

The symfs compiler paths mirror these recorded remote paths:
  /home/david/buster-fast-bench/codex-pr914-acceptance-20261030/base/compiler
  /home/david/buster-fast-bench/codex-pr914-acceptance-20261030/head/compiler
The symfs also contains usr/lib/libc.so.6 and usr/lib/ld-linux-x86-64.so.2 pointing
to the exact target runtime copies. The .debug/.build-id prefix aliases resolve
to the exact original compiler bytes; they are not build-id-normalized copies.

Reproduction order:
1. Arrange the raw capture, compiler and exact runtime inputs at the paths in
   tools/finalize_receipts.sh and tools/decode_one.sh. Construct the runtime symfs
   symlinks described above. decode_one.sh constructs the compiler aliases.
   First run the commands in analysis/final-build-commands.txt and run
   decode_grid.sh once to create the baseline text streams needed by the fault
   controls. This preliminary preparation is not the final receipt pass.
2. Run finalize_receipts.sh. It records the exact compiler commands, builds the
   reader/adapter/controls, hashes sources, all executed tools, runtime libraries,
   measured binaries and the six raw inputs before the final controls/analysis.
3. The controls must pass and decode_grid.sh must finish with its explicit
   six-profile canonical-grid success line. Every constituent command is checked;
   there is no background-job success inferred from a bare wait.
4. The final input/tool identity check must match every pre-analysis hash.

Canonical grid, 30 fresh successful measured compiler processes per profile:
  base-safe-p1, base-safe-p2, base-safe-p3-retry
  head-safe-p1, head-safe-p2, head-safe-p3-retry
The third pair uses the same explicit larger perf buffer on both sides. Earlier
p3 files are rejected/private and are not part of this accepted grid.

Each decode first obtains the complete compiler primary-IP stream with perf
script -G, without selecting function names. The second obtains its full CFI
chains with the original narrowly guarded LD_PRELOAD adapter. Their hashes bind
the large derived text streams; these streams can be regenerated from the raw
assets rather than stored as Git blobs. The per-profile JSON, coverage sidecar,
compact target proof CSV and empty stderr files are retained here.

The reader supports this fixed capture format, not arbitrary perf.data files.
It checks header/data/feature bounds, sample format and register/stack metadata,
and rejects malformed, truncated, unsupported, lost or throttled records. It
sorts COMM/MMAP2 records and samples by timestamp to bind sample-time exec epochs
and exact libc load bias, excluding pre-compiler process epochs from the cycle
denominator. Raw source samples must agree with decoded PID/TID/IP/period order.

Direct target work is check_input_intrinsic_initialize plus the candidate's
outlined check_input_intrinsic_lookup. Baseline search/filter-equivalent work is
inlined in initialization. The emitted test-only filter copy is not a production
callee and is not included. For every direct-family sample the reader checks
ELF CFI, captured register IP/SP, computed CFA, actual saved return-address bytes
and the displayed parent E8 call target. For libc leaves whose immediate caller
is in that family, memcmp attribution additionally proves the exact E8 to PLT,
PLT indirect jump to GOT, and named dynamic relocation. This does not identify
memcmp by global symbol counts or private IFUNC symbol spelling.

The denominator is the sum of reported primary sample periods in compiler exec
epochs, including nonuser/skid IPs. Target results are period-weighted sampled
user-cycle estimates. They are not exact accumulated function counters and do
not account for unsampled residual periods. Direct-family body work and its
proven memcmp calls are separate categories. Other immediate libc calls, absent
or short chains and nonuser/skid coverage are reported separately. No sum here
claims the full inclusive initializer cost.

Fault controls:
  reuse_exec_test.c: six same-file ET_EXEC reuse/delegation controls, each with a
  new Dwfl session; wrong module name, different filename, ET_DYN, add_p_vaddr and
  first registration delegate. The adapter is scoped to immutable files and the
  actual single-threaded decoder lifecycle, not arbitrary reporting sessions.
  audit_fixture.c: one valid synthetic record set plus LOST, LOST_SAMPLES,
  THROTTLE, UNTHROTTLE, zero record size, unsupported sample mask, short sample,
  invalid register ABI and truncated-data negative cases.
  text_fixture.c: missing primary event, corrupted captured-family caller,
  wrong primary IP and surplus primary event negative cases.
The synthetic audit bytes contain no sampled process/environment payload.
Large text mutations and the duplicate-name binary used only for controls stay
private; their hashes and the original fixture sources/receipt outputs suffice
to reproduce them from the eligible assets.
