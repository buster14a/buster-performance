# Target-feature diagnostics with retained conditions

This tests [Buster PR #3226 at d44ba035e](https://github.com/buster14a/buster/commit/d44ba035e84172eaac4ddd4b4b3339bb4fd34b9b). Six target-attribute or target-builtin variants appear behind seven guard expressions in nine control-flow positions. Each case runs with and without debug. The matrix includes reachable and unreachable paths, nested branches, calls to target-specific functions, allowed and disallowed BMI2 uses, and a constant-return function that can enter the window separately.

All 756 comparisons between the ordinary and condition-option compiler matched the exit status, stdout, stderr and complete object where emitted. Of them, 438 emitted objects. Ordinary Buster and pinned Clang disagreed on diagnostic text or exit status in 100 cases. The [recorded diagnostics](diagnostics.tar.xz) include all three outputs from those cases. A separate syntax-only stage probe observed a window admission in 378 cases, with actual condition admissions in 108. Every such condition admission occurred without debug.

[results.tsv](results.tsv) lists the case, debug mode, ordinary and option-on Buster status, Clang status, full ordinary/option match, ordinary/Clang diagnostic match, total window admissions and condition admissions. A value of −1 in the overall admissions column means the stage probe produced no generic counter. To repeat, set `BUSTER_TEST_CLANG` to the pinned LLVM 23.1.4 compiler and run `python3 matrix.py PATH_TO_BUSTER OUTPUT --node-window-conditions`.
