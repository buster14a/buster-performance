# Restoring only changed DWARF carrier facts

[PR #3141](https://github.com/buster14a/buster/pull/3141) compares [a8ce751149](https://github.com/buster14a/buster/commit/a8ce751149fcc6e7f427d01a329ca4a5ce95276c) with [a3b37ffc94](https://github.com/buster14a/buster/commit/a3b37ffc943b47d408c8948266d72dc922490612).

The fixed-point solver queues changed value IDs that only the later DWARF location publisher consumes. It discarded 1,021,837 queued entries across 116,629 block visits on a SQLite debug compilation. Suppress those additions in the solver. When entering a block, both passes now restore only the changed carrier facts. Incoming places are unique. Moving each to its position at the front of the known list leaves precisely the absent places at the tail. Existing reverse links and the live value-change queue stay current.

A 512-row dense reference checks carrier additions, substitutions, permutations, repeated rows, missing carriers and the exact changed-value set. The debugger suite passed 4,069 checks. All 1,336 frozen musl objects, 70 Lua/SQLite application objects, both linked Lua binaries and ten script runs matched the parent with debug information enabled.

In eight paired local Ryzen 9 7940HS compiles, this saved 0.455% of retired instructions on SQLite at both debug optimization levels and 0.280% on the Lua parser. The Lua VM used 0.032% more instructions. SQLite cycle changes varied across pairs. The release SQLite control was effectively unchanged. Direct Ryzen 7 9700X confirmation is pending.

Part of #2542. Stacked on #3135.

The separate [instrumented build](restoration-counts.tsv) regenerated byte-identical SQLite, Lua VM and Lua parser debug objects. In SQLite the solver kept 777,819 of 1,001,087 incoming facts unchanged. The publisher kept 408,251 of 439,952. The [paired production runs](restore-summary.txt) include the Lua VM instruction increase. The smaller [queue-only](paired.txt) and [single-successor carry](carry-summary.txt) experiments provide comparisons.
