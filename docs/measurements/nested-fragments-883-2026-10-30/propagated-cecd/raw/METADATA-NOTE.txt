Receipt label clarification, 2026-10-30

The common run-one.sh records `instrumented_units=41` in metadata-counts.txt
for ordinary builds by initializing that variable to the total unit count.
For ordinary mode that field is a generic unit-count alias, not a sanitizer
instrumentation count. The raw metadata files and frozen controller are retained
unchanged; no build, test or proof is repeated to replace them.

The actual ordinary native and baseline compilation arguments contain no
-fsanitize option. Each has 41 O3 units and zero sanitizer-instrumented units.
The actual address native/baseline arguments have all 41 O3 units carrying
address,undefined,bounds; thread native has all 41 O3 units carrying thread.
metadata-summary.tsv derives these counts from the actual retained compilation
metadata and uses `sanitized_units` to state this distinction explicitly.

The ordinary `metadata=0` gate validated a full 41-unit O3 build. It establishes
no ordinary sanitizer coverage. Sanitizer build coverage claims apply only to
the two address configurations and the thread configuration, verified directly
from their flags and fresh detector controls. This naming correction changes
no source, executable, result, runtime policy or qualification scope.
