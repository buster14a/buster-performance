COUNT BOUNDARIES

The trace is in c_check_program_fragment.c, emitted at the end of each call to
check_lower_fragment. Production dispatch is in c_check_program_batch.c:
  existing adjacent leaf fast path has failed;
  root operator belongs to the supported fragment operator set;
  child indices precede the root;
  at least one direct child is not CHECK_OP_VALUE.
Therefore all reported counts describe attempted roots which reached that gate.
They omit leaf-fast-path successes and roots rejected before the fragment call.
They are NOT an all-expression rejection histogram or a global coverage fraction.

Schema: lower-fragment root=U32 visited=U32 result=U32 entries=U32
Result codes: 0=ok,1=order,2=bound,3=operator,4=effect,5=type,
  6=conversion,7=payload,8=capacity.
visited is the nodes visited before the first refusal, capped at 16; a refusal's
visited value need not be the complete subtree's size. Failed attempts emit 0 entries.
Accepted visits/entries are the fragment's accounted nodes/emitted typed entries,
not native instruction counts. Fallback may later attempt descendant roots.
Root IDs are graph indices and may repeat across separately processed graphs;
do not deduplicate them, infer unique source expressions, or claim function
attribution from this log.
Run one lane to keep stderr records serial. A scalar-host build has no fragment
implementation; verify BUSTER_HOST_VECTOR=1. The current native laptop meets it.
The trace stream and aggregation contain NO timings. Never time the trace build.

PREPARED TOOL

fragment-inventory.c is original C17. It reads stderr, requires at least one valid
attempt record, rejects malformed/unknown-code/out-of-range records, and emits TSV
counts by outcome, visited-count histograms and accepted-entry histograms. It
does not emit percentages or reinterpret unrelated diagnostic lines as attempts.
Its aggregation was checked using fixture.trace (all 9 outcomes), with malformed
visited 17, numeric overflow/sign, embedded NUL with trailing junk, buffered stdout
failure (/dev/full) and no-trace negative controls. These are tool checks, not
corpus results. Repeated root IDs remain valid records, without deduplication.
