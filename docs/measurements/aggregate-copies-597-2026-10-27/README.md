# Bounded aggregate assignments (#597)

Compiler change: [buster#635](https://github.com/buster14a/buster/pull/635).

This compares unmodified Buster `92c025e71856d13eb34247477c5294d2cead139e`
with `03d79f50177fc437cc14f9ae0ced825db963c632`. Both use the same release
build, `BUSTER_DEBUG_INFO=0 ./build.sh`, with Clang 23.1.1 on the AMD Ryzen 7
9700X. Every target build, test and benchmark run takes the shared
`~/buster-fast-bench/exclusive.sh` lock. Timings use CPU 2 and one compiler
lane; no machine settings were changed.

The fixed producer keeps inline COPY through 256 bytes and calls the existing
runtime `memmove` interface for larger nonvolatile copies. The normal call ABI
preserves live values and the returned destination carries a consumed
assignment's value. Volatile copies keep their existing inline accesses,
including through comma, conditional, selected and statement expressions.

## Results

For the discarded assignment, the output is bounded at six typed entries,
11 machine records and 43 `.text` bytes for every tested size above 256,
through 262144 bytes. At 8192 bytes this removes 99.3% of the caller's text
and improves the hot-buffer copy median by 2.23 times.

| Object bytes | Baseline typed / records / text bytes | Fixed typed / records / text bytes | Baseline / fixed runtime ns per call |
| ---: | ---: | ---: | ---: |
| 256 | 4 / 35 / 181 | 4 / 35 / 181 | 1.810 / 1.811 |
| 1024 | 27 / 144 / 765 | 6 / 11 / 43 | 6.672 / 3.513 |
| 8192 | 223 / 1152 / 6197 | 6 / 11 / 43 | 52.659 / 23.647 |
| 16384 | code-output capacity failure | 6 / 11 / 43 | unavailable / 46.721 |
| 262144 | code-output capacity failure | 6 / 11 / 43 | unavailable / 2858.645 |

All 1386 measured fixed-build compilations succeeded. The baseline succeeds
1089 times and fails 297 times: all three forms at 16384, 65536 and 262144
bytes fail all 33 attempts with `code output capacity exhausted`. These failures
are not timings to compare. All 93 native guard processes pass; each runtime
median uses 24 samples from three fresh processes. Consumed assignment values
and self-assignment also have bounded output. The 8192-byte self-assignment
median falls from 52.636 to 1.984 ns per call.

The 18 baseline/fixed objects at 16, 32, 64, 128, 255 and 256 bytes, across
all three forms, are byte-identical. Forced-call screening supports retaining
the existing 256-byte inline bound: calls cost about 1.6–1.8 ns at 16–128
bytes, against about 0.7–1.0 ns inline; the 256-byte discarded copy is roughly
tied (1.810 ns inline, 1.823 ns forced call). This does not establish one
optimal threshold for every alignment and use. In particular, the call at
257 bytes is slower: discarded copy 2.235 to 2.690 ns (+20.4%, +0.455 ns),
consumed result 2.333 to 2.989 ns (+28.1%, +0.656 ns), and self-assignment
2.386 to 4.669 ns (+95.7%, +2.283 ns). All three improve at the next sampled
size, 512 bytes. Odd-size 255-byte forced calls can also beat inline copies.

Fresh-process compilation is about 1.43 ms with overlapping ranges. There is
no demonstrated compile-time speedup: discarded 8192-byte input medians are
1.436415 ms baseline and 1.431515 ms fixed. Median peak RSS there is 22032
versus 21972 KB; the fixed 262144-byte case uses 21980 KB. Individual
8192-byte stage captures are lower/Tier 0/encode 0.020/0.005/0.002 ms
baseline and 0.028/0.009/0.001 ms fixed. These very short single captures
do not establish a stage-time improvement.

The frozen-SQLite control has a 147.395 ms baseline median (145.809–148.755)
and 148.557 ms fixed median (147.037–149.868), a 0.79% increase in this
single-placement comparison with overlapping ranges. Peak RSS medians are
512864 and 512872 KB. This is not a corpus speedup or proof of no regression;
no instruction-count or code-placement campaign was run. The change fixes
unbounded expansion and the large generated-code cases, with the boundary
and control costs above left visible.

`summary.csv` is generated by `summarize.c` from the raw logs. Compile groups
with zero successes have zero-valued timing fields to mean unavailable, not
zero cost. `logs/compile-0.csv` retains all 2772 measured process outcomes.
The object-section, disassembly, symbol and small-object identity logs were
read locally from the target-built objects after the run; they are static
metadata, not additional off-target timing measurements.

## Method

`generate.c` creates tiny original C inputs with a fixed array bound: a discarded
assignment (`copy`), a consumed assignment (`kept`, returning its last byte),
and self-assignment (`same`). Sizes are 16, 32, 64, 128, 255, 256, 257, 512,
1024, 4096, 8192, 16384, 65536 and 262144 bytes. All three functions are
compiled separately so each baseline failure is visible independently.

`qualify.sh` runs one bounded comparison, including preparation of its own C
tools and generated native consumers. `compare.c` rotates baseline/head order
across two warmups and 33 measured fresh processes per input. Raw rows include
exit status, monotonic wall time, user/system time, peak RSS and minor faults.
Failed compilations are reported as failures, not speedups. Separate
`--time-stages --verify` captures record phase costs, and the existing
`benchmark-backend-source --only vector` reader records typed entries and
machine records. The phase captures are individual diagnostic samples, not
33-sample stage medians.

`runtime.c` links the three generated functions with a Clang `-O2` consumer.
It places both objects immediately before inaccessible pages, checks 64-byte
prefix canaries, verifies every byte and consumed result, and exercises both
same-pointer arguments and explicit self-assignment. Eleven changing byte
patterns are checked before timing. Each process calibrates to at least 10 ms
per sample, then reports eight samples of each operation. Three fresh
processes per available variant rotate baseline/head order. Small forced
`memmove` variants screen the inline/call boundary; their lengths have the
correct unsigned-long argument type.

These are hot-buffer generated-program measurements. They do not establish
cold-memory bandwidth or corpus-wide generated-code gains. The library uses
its normal runtime ISA selection; the generated callers retain the default
x86-64 target. No compiler-host AVX-512 instruction is introduced into them.

`campaign.sh control` compares the same builds on the frozen SQLite
amalgamation, with 33 rotated default/instrumented/reference samples.
The reference is the baseline Buster executable. Source hashes, binary
hashes, exact commands and CPU/toolchain identities accompany the raw logs.

## Correctness and provenance

The committed focused tests pass 374 checks locally, including scalar/vector
agreement, bounded output through 262144 bytes, threshold/odd sizes, native
bytes, consumed/chained values, self-assignment, argument/initializer/return
copies, existing runtime declarations, mixed runtime dependencies and volatile
value forwarding. The former lost-qualifier implementation fails the new
forwarding probe. `focused.sh` reproducibly compiles just these tests into an
original test wrapper; it does not alter the production compiler. All five
release test groups pass on the 9700X in 42.5 seconds: checker (265897 checks),
native driver/runtime binding (21591), function lanes/runtime-symbol determinism
(2749), Tier 0 with Clang cross-checks (234706), and native/object-link scalar
and vector aggregate assignments (four successful runs). The checker includes
the committed copy regressions. These are the named release groups, not a
sanitizer or full source-corpus campaign. Required GitHub CI is tracked
separately on the compiler PR.

To reproduce, arrange exact release builds at sibling `../base` and `../head`
and put this directory at `../evidence`. Preserve `source-head.sha256`, then
run `qualify.sh` under the shared host lock, capturing stdout/stderr as
`logs/compile-0.csv` and `logs/compile-0.err`. Run `campaign.sh tests` and
`campaign.sh control` separately; each acquires the lock itself. Compile
`summarize.c` with Clang and redirect its output to `summary.csv`. The
`campaign.sh qualify` case documents the static `size`, `objdump`, `readelf`
and `cmp` readers; the final measured run used `qualify.sh` to include its
preparation and source-identity checks in the same lock hold.

All harnesses, generated C fixtures and this report are original material under
Apache-2.0 WITH LLVM-exception. The harnesses reuse Buster's existing command
interfaces and the committed compiler tests. Clang, system libc and the frozen
SQLite source run externally; no external implementation or corpus source is
incorporated. Supporting generated binaries and objects are reproducible and
are not committed.
