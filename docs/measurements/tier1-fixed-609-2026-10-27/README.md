# Tier 1 fixed-register filtering, #609

This record qualifies the allocator preparation change for
[Buster #609](https://github.com/buster14a/buster/issues/609).
Baseline: [`92c025e71856d13eb34247477c5294d2cead139e`](https://github.com/buster14a/buster/commit/92c025e71856d13eb34247477c5294d2cead139e).
Candidate compiler code: [`9a652c025dbd6ef39185650932e0802828b7732a`](https://github.com/buster14a/buster/commit/9a652c025dbd6ef39185650932e0802828b7732a).
[`candidate.patch`](candidate.patch) contains the allocator and test changes
against that baseline. Documentation changes do not affect these source bytes.

The production vector allocator reuses the existing end-event order and dead
position buckets. Before querying `[start,end)`, it incorporates fixed ranges
whose starts are strictly less than `end`. A prefix maximum end for each
class/register identifies exactly the fixed-register union intersecting that
value interval. The whole-interval conservative mask policy is unchanged.
Register-lane maximum updates and queries use two 16-lane vectors. The index
cost is O(positions + fixed ranges + events), with four scratch bytes per fixed
range and a 256-byte stack table. The retained vector cross-product is selected
only when pairs <= `positions + 16*(intervals + fixed ranges)`, so its work is
bounded linearly too. The scalar API retains the independent cross-product.

## Inputs and scope

All inputs are original synthetic fixtures generated by `measure.c`, with no
required-use records. `allocation-tests.c` separately runs the production
allocator suite, including required-use, guarded-tail, capacity and native tests.

| Shape | Construction |
| --- | --- |
| 0, sparse | N values `[2*i,2*i+1)`, N fixed ranges `[2*i+1,2*i+2)`, class 0, allowed mask 3, fixed mask 1, position count 2*N: exactly the zero-overlap issue family. N = 256, 512, 1024, 2048, 4096, 8192. |
| 0, no fixed | Identical values and position count, F = 0. Event construction, coloring and the rest of allocation remain present. |
| 1, dense | Every value spans `[0,2*N)`, with N one-position fixed ranges and mask 1. The conservative policy forces the remaining single-register pressure/spill path. N = 256, 8192. |
| 2, calls | Values `[2*i,2*i+32)`, F = N/8 call phases `[16*f+1,16*f+2)`, allowed GPR mask `0xffef`, SysV caller-clobber mask `0xfc7`. N = 256, 8192. This is a realistic constraint shape, not a current-caller census. |
| 3, mixed | Alternating GPR/vector classes, including vector register 31; half the fixed ranges overlap their corresponding value and half only touch it. N = 256, 8192. |
| Tiny | Shape 0 with N = 1, 8, 16, 32 and F = 0, 1, 4, 8, 16. The position domain is enlarged when F > N so every fixed range remains valid. |

Current-caller relevance is a static source survey, retained in
[`caller-relevance.txt`](caller-relevance.txt). The single native allocation
point uses the `Tier1AllocationInput` constructed by `tier1_liveness_build`.
That initializer leaves `fixed` zeroed; `tier1_emit_prepare` copies it and
changes allowed masks and required uses, and preserves calls separately.
Consequently **all allocations from the current native producer have F = 0**;
it cannot currently generate a large F. These measurements establish API
scalability, not a default Tier 0 or native-source compilation speedup.

## Measurement method

`baseline.c` and `candidate.c` include their exact unmodified allocator
revisions in matching separate translation units. Both export one non-inlined,
64-byte-aligned entry point; the caller uses the same call boundary for each.
`measure.c` includes the candidate only for types and the fixed-filter kernels.
All are compiled into one executable with Clang,
`-O3 -march=native -fwrapv -funsigned-char -fno-strict-aliasing -Wall -Werror`,
and linked with `-pthread`. Baseline and candidate functions have separate
code addresses; small differences can include layout effects.

Before timing each case, compare all semantic allocation columns and counts,
including pressure, fragment order, locations and spill identities. Separately
compare the candidate masks with the scalar cross-product. These comparisons
are untimed. The deliberately quadratic fragment verifier is not timed or
invoked on the large scaling cases.

- **Whole:** validation, arena allocation, event construction, fixed filtering,
  pressure/coloring or constrained assignment, output publication and reset.
- **Fixed:** the retained old vector cross-product versus the candidate
  filtering entry point, starting with already constructed production-order
  events. Includes copying allowed masks, index construction, bucket clearing,
  all fixed updates/queries, scratch allocation and reset. Event construction
  and coloring are excluded. For F=0 this probe measures copying/entry overhead;
  production skips the filtering call entirely. Use the whole F=0 control for
  caller relevance. Do not subtract its median from the whole median;
  their cache states and repetition counts differ.

Each variant calibrates independently to at least 1 ms per batch, then records
11 samples, alternating baseline/candidate order by sample. Each measured batch
has an untimed warmup call. Two fresh normal processes cover all input cases.
`--conditioned` covers the four large fixed-range shapes, with at least 200 ms
of the scalar cross-product before **each** baseline and candidate sample.
`CLOCK_MONOTONIC_RAW` supplies nanoseconds; no instruction/cycle/energy claims
are inferred from these wall times. Raw individual samples are in the logs.
`summarize.c` reports medians of process medians and their process ranges.

The build and qualification benchmark acquire the shared lock separately.
`campaign.c` owns sequential fresh sample processes and the native preflight;
it caps the entire benchmark at 90 seconds. `run.sh` pins it and its children
to CPU 2. The lock is released when this one bounded benchmark run finishes.
The build receipt records the CPU, compiler, source and executable identities.
The peak-byte columns are **logical retained + scratch allocator bytes**, not
RSS or reserved virtual address space. Indexed cases add 4*F bytes; tiny and
no-fixed cases add no index allocation. No additional output bytes are retained.

## Reproduction

Use fresh baseline and candidate checkouts at the pins above, and this evidence
directory. On the approved host:

```sh
EXCLUSIVE_OWNER=codex-609 EXCLUSIVE_TITLE='Buster #609 build' \
EXCLUSIVE_LINK=https://github.com/buster14a/buster/issues/609 \
~/buster-fast-bench/exclusive.sh bash build.sh /absolute/base /absolute/head
bash run.sh
clang -O2 -Wall -Wextra -Werror summarize.c -o summarize
./summarize logs/process-1.csv logs/process-2.csv logs/conditioned.csv > summary.csv
```

The same `measure.c` can run one case with `SHAPE N F AFTER_SCALAR_MS` or check
all normal cases without timing with `--verify`. `allocation-tests.c` invokes
the exact suite included by Buster's `test-tier1-allocation` command.

Local diagnostics used the same optimized flags for the focused suite, and
`-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer` plus the same host
and semantic flags for **both** source variants of `measure --verify`.
These local runs are correctness checks and contribute no 9700X timing points.

## Provenance

The wrappers, input generators, comparator, timing/summary code and shell glue
are original work under Apache-2.0 WITH LLVM-exception. They consume existing
Buster code at the declared pins under its retained component licenses. No
external implementation, corpus, instruction dataset or fixture was imported.
Clang and binutils run externally. The generated code inspection is retained
as `fixed-filter.s`; the new index uses contiguous register-table vectors,
without gathers or scatters in that filtering function.
