# Interpreter image name resolution

The six-unit musl rand48 image took 374 candidate-symbol visits and 3,032 external-binding comparisons inside the base resolver. The indexed resolver collected nine definitions and examined 17 occupied name slots, including construction. All six generated ELF objects and the program's checksum matched. This measures work in the interpreter's image builder. [Issue #3032](https://github.com/buster14a/buster/issues/3032)

Base `6427879e1143026a12fb0388a20bdea1fe4b2bc5` and candidate `87a8c702b0852547c129fd3f884588e719dfd119` used Clang 23.1.4, LLVM revision `7a941dfb2877a0b8cf30323fefa85ad019e0b0f5`, CMake 4.4.3, and Ninja 1.13.2. Both builds ran in the same job on a GitHub-hosted Ubuntu 26.04 AMD EPYC 9V45. The repository's vector probe passed. The job used `./build.sh --config Release`, `BUSTER_HOST_ARCH=vector`, `BUSTER_DEBUG_INFO=0`, and the default unsanitized build. An earlier hosted job established the fresh-main baseline before the index was written. A base candidate is one visit to a symbol in the nested definition search. A head candidate is an occupied index slot whose selected symbol is compared to the requested spelling. The two head counts include collisions during table construction and reference resolution respectively. The definitions column counts every input definition consumed by construction. Empty slots, hash calculations and zeroing the table are outside the occupied-slot count. The index bytes are the table capacity times its 16-byte entry size. Up to 32 slots use a 512-byte stack array. Larger tables use temporary arena storage. The definition list uses the output binding arrays before publication.

The external counter counts each entry examined by `interpreter_link_external`. Inside the resolver it reached zero for every indexed case. During the preceding symbol initialization, base and head both made 176 such comparisons for musl and 83,460 for 128 generated C units. Duplicate-binding validation is a separate loop. These are operation counts. Host timing and Zen 5 throughput were outside this qualification.

## Inputs and correctness

- `interpret-c` prepared 8, 32 and 128 separate C files generated by `generate.c`. Each unit defines data and a getter that follows a local pointer relocated to the next unit's data. Main calls all getters. Both Buster builds and Clang printed sums of 36, 528 and 8,256 and exited successfully.
- The real library input uses five byte-verified production sources from Zig 0.14.1's vendored musl 1.2.5. The driver seeds the shared generator, calls through a relocated function pointer and mixes 64 pairs of values. The build defines musl's internal `hidden` annotation as empty with host headers. Both interpreters and Clang printed `rand48 checksum 13500281`. The `-c` comparison covered the driver and all five production units, including the data-only seed object. [Pinned musl sources](https://github.com/ziglang/zig/tree/d03a147ea0a590ca711b3db07106effc559b0fc6/lib/libc/musl/src/prng)
- `tests/interpreter/units-main.c` and `units-library.c` exercised cross-unit data, weak definitions, callable tokens, and local identity. Both interpreters and Clang printed `typed units: 1`.
- Three temporary `test-interpreter-link` cases built larger Link images directly. Each unit has an exported data definition, a reference to the next unit, a callable token and a local alias. The external bindings arrive in reverse unit order. Each case checks relocated bytes and follows every ring edge.
- The same regression fixtures ran against both implementations. They distinguish an earlier unresolved symbol from two different duplicate spellings, check the exact conflicting input, symbol, atom and fixup, and cover aliases with different sizes and a strong code atom without a callable token. The instrumented suites each passed 42 checks. The clean PR candidate passed all 39 committed checks.

The bytewise trace comparison covered 1,581 winner records, 1,584 symbol-map records, 354 applied relocations and 27 complete materialization result tuples. Symbol addresses are represented by originating input and atom plus offset, external input and symbol, or their literal value. Each relocated field is read back and its target or size verified under the field width and addend. Each C command's stdout and exit status matched its native Clang build.

## Reproduce

On an ordinary AVX-512 Linux VM with a Buster checkout, run the following from this record's directory. The script clones the supplied checkout into a temporary directory. It builds both pinned revisions with the same toolchain and private test fixtures, compares the traces and objects, and repeats the test with the clean candidate.

```sh
bash reproduce.sh /path/to/buster
```

The command prints its comparison directory. `counts.tsv` contains the operation counts, `hosted.log` contains the measurement and verification output, and `observations.zip` contains the individual base and head stdout, counters, normalized traces, and native outputs from the paired run.
