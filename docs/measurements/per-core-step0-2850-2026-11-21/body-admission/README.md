# Admission boundaries in the frozen body streams

Step 0 admits 257,465 of the 266,707 evaluated SQLite nodes. Of these, 128,638 belong to bodies where every evaluated expression was taken and 128,827 to bodies that also contain a refused expression. There are 3,849 contiguous runs of admitted roots in the dump order. Runs of at least 64 evaluated nodes contain 196,067 taken nodes. The equivalent musl counts are 66,374 nodes in fully admitted bodies, 49,236 in mixed bodies, and 68,474 in runs of at least 64. The two original Step 0 paths agreed on every root and size. The inventory contains 2,668 SQLite body records, 2,665 with an evaluated expression, and 406,765 total typed entries. Expression ownership covers 376,035 of those entries. Control and other unowned entries require their own producer.

A second census varies the set of operators and result classes permitted in a complete expression. Scalar results alone, even with calls and ordinary memory operators allowed, yield 79,573 eligible SQLite nodes. Including void casts and void calls raises that figure to 213,980. Including address-mode aggregate operands raises it to 262,357. Excluding bit-fields, vector elements and overload heads leaves 258,252. These are structural upper bounds from the lowering's actual resolved types. An ordinary producer must also prove diagnostics, effects, type conversions, object identities, statement control and the exact native output. No cycle saving follows from this inventory.

`coverage.tsv` gives body and expression counts per corpus and policy. The compressed body and run tables retain the population behind each total. The two exported root maps are the scalar twin's and the SIMD kernel's acceptances, joined by root ordinal and checked against the independently reconstructed expression size. The post-measurement exporter adds only the two verdicts and root size to the Step 0 qualification harness. The census counts entries with expression or conversion ownership directly from the dump.
