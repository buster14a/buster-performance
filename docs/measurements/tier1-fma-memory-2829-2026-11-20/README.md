# Scalar FMA with a memory multiplicand

[Buster PR #3122](https://github.com/buster14a/buster/pull/3122) compares `a5e74c987e4603baa430ad14e50bc78294a527a3` against `7b6272d08e82bc754e714160dc13599066eaa37b`, the head of the signed-conversion change. The emitter folds a scalar load of the second multiplicand into an FMA3 instruction. It preserves which NaN payload wins when distinguishable operands are NaNs. This record covers local correctness, instruction selection and code size. The initial native comparison and scheduler-form qualification are pending.

**Native x86 semantics.** The oracle uses the parent’s hardware FMA ordering as its reference. It compares the compiler functions’ result bits and floating-point exception flags in all four rounding modes on zeros, finite values, infinities and distinct quiet and signaling NaNs. Each compiler passed 229,376 observations with digest `965b4e81dcbf9afb`. Source and disassemblies for both versions are included. The array harness additionally produced 800 matching results against the independent pinned Clang reference across the two targets, default and opt-in unrolling, and four entry-address placements.

**Generated code.** Among the frozen 25 array kernels, three families changed on the Zen 5 target. The unrolled saxpy loop’s complete function shrank from 254 to 218 bytes, dot product from 205 to 161, and matrix multiplication from 589 to 552. The exact sizes and function-byte hashes for both target modes are in `kernel-code.tsv`. All 1,336 frozen musl objects built. Each of the 38 changed objects had smaller .text, totalling 983 bytes saved. Five SQLite 3.53.2 speedtest1 verification sets produced identical verification byte counts and hashes with both Buster builds and Clang. In a separate self-host build, two Buster functions shrank by eight bytes altogether and all smoke and probe commands passed. [Self-host record](https://github.com/buster14a/buster-performance/tree/4f8812382ea2c8b279572beb9ea41f187eec22b1/docs/measurements/tier1-compile-codegen-integration-2026-11-20).

**Linked math library.** The three builds use the same frozen 300 math translation units. The harness recorded result bits and exception flags for 44 functions with 4,096 inputs in four rounding modes, or 720,896 records. The parent and candidate output files are byte-identical, SHA-256 `a64ff3fb76147ab941bc0bd640bff61f4be424f45125340e473940203f4472c0`. Both Buster builds differ from the independent Clang build in 3,234 result patterns and 22,740 sets of flags. The per-function table distinguishes NaN-only payload differences from finite or infinite differences. This establishes parent/candidate parity for the tested inputs. Hardware-independent accuracy claims require a separate numerical oracle. Build inputs, exact hashes, harness and comparison source are under `libm/`.

Build the kernel objects and linked executables with `./build-kernels.sh ABS_PARENT ABS_HEAD` and run `./verify-programs.sh`. The placement manifest records actual entries. The native runner takes the shared lock per individual invocation and records core-2 counters and load. For libm, run `python libm/build.py CORPUS ABS_PARENT ABS_HEAD ABS_CLANG` and link `libm/check.c` against each produced archive with libm. The frozen source inventory is in `libm/inputs.tsv`.
