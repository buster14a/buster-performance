Observations, not dynamic instruction attribution:

1. Base check_input_run's first control pass already tests loaded registers:
   0x107856f cmp $9,%eax; conditional branch, then on prefix roles
   0x1078678 cmp $15,%r8b and branch. Thus this site does not reload
   both token columns for every source-level helper evaluation.

   Candidate uses the already-loaded kind and role, but combines them:
   0x1078b79 mov %eax,%r9d
   0x1078b7c xor $15,%cl
   0x1078b7f xor $9,%r9b
   0x1078b83 or %cl,%r9b
   0x1078b86 je <body ownership store>

   This is a branch/integer-work tradeoff, not removal of every instruction
   at that site. It is one reason to measure a constant-false diagnostic.

2. Base's second control pass is already kind-first after LLVM optimization:
   0x107878c loads kinds, 0x1078799 tests goto, and for other tokens
   0x10787a7 cmp $15,%dil; jne; only an AMPAMP reads/tests role at
   0x10787ad cmpb $9,(%rax,%rsi,1).
   No out-of-line indirect-goto helper call exists in check_input_run.
   Candidate tests kinds through a differently ordered dispatch starting
   at 0x1078dce (AMPAMP, semicolon, then goto).

3. Base expressions contain a role-column reload/test outside the prefix
   branch at 0x108c94f..0x108c96c: load roles, compare PREFIX, then load
   kinds and compare AMPAMP. Candidate's prefix handling uses its already
   loaded role at 0x108bb7d, and the new AMPAMP case lives inside that path.

4. Base check_program's full token/parent walk reloads/tests the role for
   each unrolled token around 0x100e402..0x100e43d (and +1-token twin at
   0x100e542..0x100e56e): PREFIX test, optional AMPAMP test, then target
   marking. Candidate removes this recognition from the shared walk and
   emits the separate selected-unit vector filter, for example vpcmpeqb
   pairs at 0x100e89a/0x100e8a1 and subsequent selected-target writes.
   The source guard executes that filter only for nonzero address count.

5. Ordinary-name exclusion is unchanged in source c_check_input.c:2797ff
   and has the same instruction sequence in both native images, shifted
   by 0x650. Base 0x1083adb tests OPERAND; loads the parent and bounds;
   0x1083af6 tests LABEL; 0x1083aff tests GOTO; then:
   0x1083b04 xor $9,%dl
   0x1083b07 xor $15,%cl
   0x1083b0a or %dl,%cl
   0x1083b0c sete %al
   Candidate equivalents are 0x1084154..0x108415c.
   Both check_input_resolve_range functions have size 0x643a bytes.
   This name-exclusion predicate is outside the requested helper-only
   ablation and remains there. Its dynamic contribution is not measured
   merely by this static sequence.

These observations support a narrower statement than the issue's historical
source-level cost hypothesis: the compiler already eliminates some apparent
reloads, and one rewritten site changes code generation in a way that can
spend more integer instructions while using fewer conditional branches.
Only the coordinator's upcoming same-base diagnostic counts can quantify
the removable predicate work. No production change is made from this note.
