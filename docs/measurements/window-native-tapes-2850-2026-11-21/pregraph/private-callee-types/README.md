# Direct function decay at the source frontier

With the post-numbering reference hooks disabled throughout the translation unit, the window produced 18,480 native tapes on frozen SQLite. Its direct calls had no decay pointer in the type table at that point. The ordinary path interns many of these pointers later. Running the reference type pass after *earlier* chunks gave the producer 26,303 tapes, including 7,154 call entries. Settling only existing types and facts, interning the reader's strings, assigning graph numbers and binding comparison records left the baseline at 18,480. The eight controls use one binary and the same SQLite inputs and flags. The public pregraph/source-masks record prices a calculation with those earlier reference passes enabled.

The second binary derives direct function decay from the current source window. It takes a temporary view of the type table, creates the pointer to each referenced function declaration if necessary, supplies its decay to the window checker, then rolls back after capturing the native tape. It records the function type as the enduring key for each direct call. With all reference type passes disabled it produces 25,348 native tapes, 122,910 native entries and 6,980 calls. In 5,262 call entries the conversion used a pointer created in the temporary view. All 6,980 function-type keys resolved to the ordinary callee conversions with the correct conversion flags after checking. No retained root had a provisional result type in this experiment.

A second run used late graph numbering only to align each candidate with the ordinary lowering. 25,337 roots were reached. Their 122,836 native entries, including 6,979 call descriptors and 16,071 argument classes, agreed with ordinary lowering. Eleven retained expressions never reached lowering. The independent call-splice experiment is separate. This diagnostic binary's elementary native whitelist consumed 4,763 expressions with either source-only setting.

The ordinary post-check graph capture was 57,094,544 bytes in each source-only run. Both graphs and the two complete 2,061,200-byte ELF objects compared byte for byte. The capture compares the node identity, operands, source tokens, checked values, operand conversions, member offsets and argument-node indices. The two views left the same 3,445 ordinary type slots at the end of source processing. The shadow stream witness still held provisional numeric IDs in its unconverted debug receipts. In this version 6,342 raw conversion records differed across 6,204 roots, with zero full checked-value differences and zero differences in 20,128 call argument conversions. A general consumer needs an enduring recipe for each provisional type it retains. The omitted reference warning classifications are marked untested in the shadow log.

## Reproduction

Start from buster commit `84a7d3d76891d6c393497e62e6aff38f2b162fc2`. Apply `base-to-checkpoint.patch`, then either `ablation.patch` or `callee-view.patch` to separate checkouts. The latter includes the correction for the far vector tail. Build with `./build.sh` using the repository's pinned toolchain. The frozen SQLite argument vector is the same one used by the parent experiment.

Set `NODE_PROOF_NO_FP=1 NODE_PROOF_POINTERS=1 NODE_PROOF_CALLS=1 NODE_SOURCE_ROWS=1 NODE_PROOF_NATIVE=1`. For ordinary emission enable `NODE_SPLICE_FRONT=1 NODE_SPLICE_ENABLE=1 NODE_SPLICE_REPORT=1`, then run `compiler --lanes 1 -c` with the frozen arguments and an output file. The first eight rows of `sqlite.tsv` vary `NODE_CROSS_CHUNK`. The letter `n` disables all reference work, `m` settles machine types, `r` settles fact rows, `s` refreshes reader strings, `c` compares numbering, `b` binds receipts, `t` runs the reference type pass and `o` runs the original oracle. The last two use `n` with the private view unset or `NODE_CROSS_TYPE_VIEW=1`. Set `NODE_SOURCE_GRAPH_ORACLE` to a distinct output filename for each graph capture. For `bound-shadow.txt` run the second binary with `NODE_CROSS_CHUNK=b NODE_CROSS_TYPE_VIEW=1` and `measure-node-machine --shadow --window-rows --front-first --passes 0` followed by the frozen inputs. The traces document correctness and frontier coverage. No elapsed-time measurements were taken in this experiment.
