# What the source producer and graph replacement cost

Four separately compiled Release executables from Buster `84a7d3d76` produced the same SQLite ELF, native witness, stdout and diagnostics. Enabling the producer while keeping the graph added 143.96 million user instructions and 179.90 million total cycles. Replacing the graph operands on that producer removed 2,750 nodes. It added 17.47 million instructions and 1.18 million cycles. Screening logical operators at the parser narrowed the work and changed which chunks fit: 3,406 nodes disappeared, and compilation still took 141.72 million more cycles than the disabled build. [Matched objects and graph sizes](objects.tsv) · [Paired costs](paired.tsv)

A separate fresh-process clock measured median paired wall changes of +37.83 ms for keeping the graph, +5.84 ms for replacing its operands, and +40.33 ms for the lexical screen against the disabled build. All four images were run twice in each of five rounds for each measurement. The Ryzen 9 7940HS used the real frozen SQLite input and a single compilation lane. These are local costs of this implementation. The step 2 hardware gate uses the locked 9700X. [Fresh wall observations](fresh-process-wall.tsv) · [Raw PMU observations](pmu.tsv)

The screened build caused 9,762.5 additional minor faults. A separate debugger run recorded the caller and byte count of each large clear in libc’s AVX-512 memset, with a 64 KiB threshold. The screened source path added 26,885,208 bytes of such writes in reader initialization and 5,729,096 bytes in the warning-selection pass. The largest two individual clears initialize a pointer slot per potential graph node (6,241,280 bytes) and per source token (5,729,096 bytes). These counts measure bytes written, including pages which were already resident.
