# Costs of sweeping two reader chunks at once

Item 2 of [Buster #3196](https://github.com/buster14a/buster/issues/3196) asks whether a longer window amortizes the first pass over the native rows. A single Release build of [b3b6c3010](https://github.com/buster14a/buster/commit/b3b6c30102a68f47ab94247471ca4dd9924933a2) ran the same shadow under both settings on locked Ryzen 7 9700X CPU 2. All 84 invocations exited zero and both settings agreed with the lowering oracle on every admitted entry. One and two in the table mean 1,024 and 2,048 reader postorder tokens before compaction.

| Corpus | Chunks, one / two | Records swept, one / two | Admitted expressions / entries at either size | First TSC ticks per swept record, one / two | Paired first delta [range] | Paired repeat delta |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| sqlite | 611 / 310 | 321434 / 318836 | 49839 / 315461 | 8.727 / 8.035 | -0.688 [-1.303, -0.494] | -0.244 |
| lua | 241 / 138 | 91252 / 90254 | 10246 / 64738 | 12.531 / 11.557 | -0.971 [-3.223, -0.654] | -0.254 |
| musl | 2975 / 2335 | 377187 / 529886 | 40441 / 204112 | 26.117 / 17.903 | -8.367 [-9.488, -7.458] | -2.176 |

The longer window reduced the first pass per swept record in all seven paired rounds on both SQLite and Lua, satisfying item 2's cost test. On musl it swept 152,699 additional records for the same output. Per admitted record, the first pass still fell by 0.868 ticks on SQLite, 1.414 on Lua and 2.176 on musl. The total paired first-pass savings were 242,096, 100,131 and 445,628 TSC ticks respectively. [paired.tsv](paired.tsv) gives the full ranges and denominators. Recreate it with `python3 scripts/pairs.py length runs`.

Each of seven rounds on each corpus alternated one/two/two/one or its reverse, with two runs of each size. Within a round the reducer divides each reading by its own records swept and averages the two readings for each size, then computes the two-minus-one change. The table shows the median of the seven changes and their full range. These times cover the rows' sweeps within the shadow. The first experiment missed a chunk-size field on the independent comparison reader. The one-chunk musl control detected four differing chunks and stopped that campaign. Both readers use the same limit in this revision, and every reported trial comes from the corrected executable. Real compile wall time and the cost of producing the window are outside this interval. The build allocates the same scratch capacity in both modes, and the existing record cap remains 4,096. Expressions that end near a chunk boundary can change the number of records swept.

[rows.tsv](rows.tsv) retains both settings' coverage and first and repeat distributions. [runs.tar.xz](runs.tar.xz) holds every stdout, stderr and exit status. To check the report, unpack the archive, compile [scripts/summary.c](scripts/summary.c) with `cc -std=c17 -O2 -Wall -Wextra -Werror`, and run the resulting program with the extracted `runs` directory as its only argument.

To repeat the hardware measurement, apply [double-window.patch](double-window.patch) to that source commit, then use `./build.sh --config Release`. The [runner](scripts/double-window-run.sh) records the exact command, process affinity and order. Place it with [corpora.sh](scripts/corpora.sh) and [lock.sh](scripts/lock.sh) in its indicated job directory, with the binary at `result/compiler`, an empty `result/runs` directory and Lua 5.4.8 at `inputs/lua-5.4.8/src`. The SQLite and musl paths and command-line options are in the corpus script. Run the script for rounds 1 through 7, holding the campaign lock for each round and the shared host lock for each invocation. [environment.txt](environment.txt) records the binary, patch, build and host.
