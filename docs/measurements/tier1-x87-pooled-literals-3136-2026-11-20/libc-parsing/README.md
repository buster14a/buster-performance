# musl string-to-floating conversions

The complete static runtime was built from [musl v1.2.5](https://git.musl-libc.org/cgit/musl/tree/?id=0784374d561435f7c787a555aeab8ede699ed298). Each comparison program takes six genuine source objects from its candidate archive, including `strtod.c`, `floatscan.c`, and the long-double scaling and remainder functions. The linker maps verified that all six came from that archive. The resulting ELF executables have no dynamic interpreter. The exact source, object and executable identities are in [units.tsv](units.tsv) and [programs.tsv](programs.tsv).

The [driver](parser.c) checks 768 inputs apiece in four groups, using short decimal strings, long decimal mantissas and exponents, hexadecimal strings, and exceptional or malformed tokens. For each of float, double and long double it tests all four rounding modes. Each of the four compiler variants produced the same 36,864 results, including the returned bits, end pointer, errno, x87 flags and TOP, and MXCSR flags. [Per-input and format comparisons](comparison.tsv).

In the [1,152 checked 7940HS process measurements](counters.tsv.gz), each invocation made 15,360 conversions. All three Buster binaries used the same output oracle. Relative to #3134, #3136 used 4.60–5.32% fewer cycles on the hex-to-float case at four placements and 1.70–2.88% fewer on the special-to-float case. Short-decimal cases showed mixed cycle changes. The full [paired results](paired.tsv) retain the other cases, the larger changes in both directions on long decimal input, and seven within-round pairs after warm-up.
