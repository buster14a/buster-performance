FILES AND GATES

hp_method.c is the non-timing C controller. It only invokes existing Bash APIs,
the pinned Clang driver, pinned Wild through that driver, and /usr/bin/sha256sum.
Every producer child is execv argv (no shell evaluation), with exclusive raw
NUL argv, split stdout/stderr and actual exit-status artifacts. Parallel source
compiles are bounded by sched_getaffinity / distinct core_cpus_list groups;
new work stops upon observed failure and all live wrappers are waited. Original
source order controls final link order regardless of compile completion order.

Before producer probes, require canonical inputs, full qualified source-manifest
validation, exact qualified normal-image SHA, inherited shared-host lock and
pinned official Clang23.1.4/license/Wild hashes. New outputs are fresh and
outside the source tree. The source manifest must contain build.sh and every
API translation unit; the owner must supply the complete qualified archive
manifest, including included headers/support code. The controller does not
infer a full dependency graph from C text.

hp_common.c removes include/library/driver/preload overrides in its private
process environment, sets task-private tool/resource paths and explicit source
mode, and retains full selected environment via toolchain-environment.nul.
No global environment or settings are changed. HELD is checked, never invented.
The default target and successful effective C/assembler driver receipts bind
canonical Clang identity, exact triple, CPU and full ordered feature vector.
The assembler gets only the explicit pinned target/ISA and assembly operands;
C-only -D/-I/-f/-W flags remain on C commands. Direct C and -S use identical
qualified C flags. Link commands and driver receipts retain original objects,
order, -no-pie, exact Wild path and -lm/-ldl.

hp_pad.c inserts only after the unique initial page alignment of the current
.text.buster_checker section. Shift0 is byte-exact and introduces no marker,
retention flag, outside padding or extra object. hp_elf.c requires zero/direct
object semantic identity, disclosing only bounded nonsemantic metadata changes.
For nonzero shifts it requires exact intentional prefix, hot suffix, every
owned function (including zero size), symbol/addend/RELA/ADDRSIG translation,
all other object sections and supported relocations. Unsupported semantics
fail closed; alignment or instruction changes beyond the intended prefix stop.

hp_linked.c requires every selected object's hot function to translate by +S
with its identity/extent/output section retained; emit, drain and classifier
are mandatory, plus fragment when that source exists. It checks the complete
hot extent and linked nonrelocation bytes; only explicitly known relocation
operand fields are masked. It records each function address/residue and each
masked operand. Direct-normal and inside0 must BOTH match the whole qualified
normal SHA. All objects/API/assembly/driver/raw logs/settings/zero proofs are
hashed into a frozen snapshot. A final ready record binds its SHA and the
normal/source-manifest identities. Later inside steps revalidate this snapshot,
source manifest, source array, normal/zero images and toolchain before probes.
Completion markers are written only after gates and source postchecks pass.

hp_receipt.c writes complete exclusive proof/identity records and declares scope
limits. These gates attest ELF section-header geometry and nonrelocation bytes,
not PT_LOAD/runtime loading or correctness of numeric resolved relocation
operands. Pinned linker/input identities, exact zero image and separate per-image
object-preservation/semantic controls are essential additional gates. No image
is executed by the controller; no compiler-input or runtime oracle is inferred
from structural placement. Local synthetic support tests prove neither real
producer compatibility nor successful hot placement of actual binaries.
