# Finish calls in window order

The shadow checks the callee and its argument conversions together while its record is hot. A failed call becomes wide before the next call reads it. The full rule processes the failed calls once in their original postorder. The loads-only kernel retains its existing contract. The product source is Buster commit `db1209692cc37297efe32708d8c5c3ea6784dcf4` against `0e1d5b825801135bf50e79da9d546bc95209ab30`. The patch SHA-256 matches the signed commit diff.

Five alternating ABBA/BAAB rounds on locked 9700X CPU 2 compared both builds in both modes on three corpora, 120 fresh processes. On SQLite the lean kernel moved from 29.300 to 27.755 cycles per taken identifier or lookup. The median paired reduction was 1.425 in four of five rounds. The complete lean pass including given records improved by 0.865 cycles per window record in all five. Lua and musl improved by 0.280 and 0.170 on that complete pass in all five. The SQLite timed lookup loop alone used about 59.77 cycles per lookup on its first run, 4.14 fewer than its paired reference. Step 1 requires ten cycles per taken leaf or lookup. The shadow results have no effect on ordinary compilation.

All builds and modes retained the oracle's results for the records, work lists and decoys. The directed control exercises dependent calls, converted arguments, function pointers and aggregates. SQLite includes 13,323 call records, of which 35 were left. The local archive retains the corpus summaries and both versions' eight directed mode summaries.
