# Checked record member reuse across source bodies

Revision a074693634bf6ceced80d72749182fe383d65034 adds a translation-unit table for successful runtime accesses to ordinary record members. A source body can reuse the full semantic result on a repeated type and member after its record is complete at the current source position. This includes the type, operand conversion and record-relative bit offset. The original action computes each first result and handles constant evaluation, overloads, vector types, exceptional input payloads and nonmatching qualifiers.

SQLite's resident body reader emits 319,280 nodes. Of 47,508 casts, 43,126 already use the existing discard shortcut. Among its 32,623 record accesses, 26,097 reused the ordinary checker's member result. Buster reused 20,715. The ordinary and cached modes produced identical checked body fingerprints for all 2,674 SQLite bodies and all 8,654 Buster trials that completed semantic checking. Both complete ELF objects matched the independent ordinary compiler. The corpus receipts include rejected Buster native trials because they still ran the local semantic rules.

The focused 35-case matrix exercised const and volatile fields, bit-fields, anonymous members, declaration shadowing, completed and incomplete records, vector names and missing members under five warning policies. All native statuses, objects, standard output and diagnostics matched. All 30 cases in the supported fixture set also matched Clang's status and executable result. The ordinary production compiler and both experimental modes reject the same vector-pointer swizzle at the same location on the other five. Clang accepts that expression.

The functional checker unit was linked with debugging optimization settings for quick event and byte comparisons. The separately built optimized checker uses the pinned Develop IR splitter and 48 O3 partitions, linked against the existing Develop objects for the other units. The paired timing harness pins both arms through a single shared core lease and checks the complete ELF digest on each execution.

## Local optimized measurements

On the Ryzen 9 7940HS, 12 fresh wall pairs and eight counter pairs ran with a single core lease and alternating order. Four separate paired stage reports complete the 48 whole-object comparisons. All object digests matched 2238999c41e256cc9c14ddbe21e379f0b3c09df25fb642b056e18b8a7ea773a0. The binary SHA-256 was d5df46c3bc16910edcbc09ac7243e1c748f06bcacc7dde5ad19c10ace2655770.

The paired user-instruction reduction was 14,251,078 (0.867%) and ranged from 14.219M to 14.280M across all eight pairs. Instruction sampling showed 8,374 samples in check_graph_run in the ordinary rule arm. The cached rule had 7,682 samples there and 115 in its separate eligibility helper, at 20,003 retired instructions per sample. The source action table added 128 KiB of median paired RSS and 45 minor faults. The local wall-time median paired difference was -4.8285 ms (8 of 12 faster, pair range -134.8 to +20.0 ms). The median paired cycle change was +28,870,307 (+3.13%, 5 of 8 slower). Four separately instrumented source-input stages had a +1.540 ms paired median. These runs establish a repeatable instruction reduction and leave the throughput effect unresolved on this host.

The compressed sqlite-members.tsv file maps each of the 32,623 checked members to its unique PP output row. It contains all 1,548 canonical name identities, 2,133 resolved member slots and 344 record type identities used by these accesses. The source-first reader emitted an exact object during that capture. The raw performance data, sample rankings, semantic witnesses and source patch accompany the table.
