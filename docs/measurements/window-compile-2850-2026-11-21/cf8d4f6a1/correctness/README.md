# Ordinary compiler initializer storage
The baseline is unmodified b86eadcbd3d6c5cdf687f6b67b0281df2ac34034. The third candidate, cf8d4f6a127a6e68d2b9c8ed5d57d9fc66332f94, keeps the original scratch-resident payload arrays, tracks initialized declaration owners with a bit, and checks the existing first-visit state before reading an initializer finish head. This removes both full-size sentinel fills. The separate poison-test patch adds checks for declaration zero, dirty input and guard boundaries. The 512-function deferred-lane fixture compiles to identical executable code in all six ordinary and changed lane schedules and returns success.

The eleven policies produced matching status, complete diagnostics and objects on 3,400 paired invocations. The compressed tables preserve individual translation units and the matched digests. The pinned Clang 23.1.4 checker tests also passed in all eight shards.

All three candidate layouts paid for a true parent-versus-candidate full SQLite compilation on the locked Ryzen 7 9700X. None established a consistent elapsed-time improvement. The sparse-directory candidate decreased paired cycle counts in all three rounds while two wall rounds slowed. The relative-index candidate raised faults and showed mixed cycles and wall. The third candidate's median wall difference was −0.0175 ms, spanning −0.068 to +0.134 ms, and its median cycles difference was +0.1483 per token. Each candidate remains experimental. Local single-core Zen 4 measurements in marked-cost.tsv are supplementary. The CPU pin differs from the 9700X native campaign.
