# Native code and relocation targets present in completed source prefixes

The active preprocessor printed each prefix after a complete original C declaration. A separate native compilation consumed that preprocessed input and an independent comparator read the resulting ELF. At the SQLite checkpoint with 606,167 grammar tokens, all 1,251 emitted function bodies matched their complete original-source instruction bytes. Of these, 306 already had identical relocation keys by raw symbol or section name, type, position and addend. Translating each relocation target to its named object plus relative addend matched all the references in 1,238 functions. Taking either raw or named equality covered 1,239 functions and 314,368 instruction bytes. Twelve functions still had at least one unresolved reference under those rules. This experiment uses the completed reference ELF to check both sides of the correspondence. [Comparator](relocations.py), [SQLite results](sqlite-symbolic.tsv), [Buster results](main-symbolic.tsv).

On the final complete preprocessed SQLite run, all 2,668 functions, 1,065,651 text bytes and relative relocation keys matched the ordinary original-source ELF. On Buster, 1,298 uniquely named full-length functions matched and six duplicate symbols totaling 48 bytes were excluded. The full ELF headers can differ when a compilation names the printed input. Some partial Buster checkpoints also emit fewer selected functions because the suffix has not introduced their uses.
