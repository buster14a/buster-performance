# Paired frozen SQLite compiler measurements

Each exact-head record uses the same 9,507,037-byte SQLite source and defines as the [original opt-in record](../84a7d3d76/README.md), with 716,136 preprocessed tokens and a single lane. The frozen input SHA-256 is 0a409f1633283fa31a9126b11fbfd64a1991c5d30defad07e5745d4667f5e23d. Clang 23.1.4 built the Release compilers on the Ryzen 7 9700X.

The named control, candidate flag-off and candidate flag-on each occupied two symmetric positions per round. Odd rounds used control, off, on, on, off, control. Even rounds used on, control, off, off, control, on. All processes ran on CPU 2 with the shared host lock. The batch queue rotated after each balanced round. Each configuration has seven PMU rounds (42 compiles) and seven separate wall rounds (42 timed compiles). Each wall sample followed one warm-up of the same mode in the same position. PMU samples ran in a fresh process with user and kernel cycles and instructions enabled for 100% of the time. The three additional stage compiles provided counts and three further compiles used `-Wall -Wextra` for independent diagnostic comparisons.

Per-mode medians use the average of the two identical mode positions in each round. Each paired difference subtracts the two mode means within its round, before taking the median across rounds. A difference between overall medians can differ from the paired median. Elapsed source throughput is decimal MB/s. All object digests were collected after successful compilation. The archive's `duration_time` perf tool event always returned zero. Reported wall time comes from the compiler's monotonic `time-runs` child measurement.

Each record includes raw process counters, child wall reports and a table for faults and system time. Host transparent huge pages were set to `always`, 2 MiB pages to `inherit`, defragmentation to `madvise` and shmem huge pages to `never` on Linux 6.18.50-2-lts. These are host policies. Per-mapping huge-page state was not observed. Separate [fixed allocation-policy controls](../../switch-selector-2850-2026-11-21/9700x/) found both a roughly 5,760-fault band and a roughly 60,000-fault band in comparable ordinary compiles. The records identify observed high-fault samples and give an explicit sensitivity check where applicable.
