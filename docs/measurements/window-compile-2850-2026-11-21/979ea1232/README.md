# Persistent source bindings across the preprocessing checkpoint

The preprocessor remained active while a prefix checker captured resolved local and parameter references. The ordinary reader then consumed each retained source token and declaration at its original point, validated the live symbol and type, emitted the canonical event and reused the accepted answer during final declaration publication. The row contains three 32-bit values. It retains no type-table pointer from the temporary checker.

At checkpoint 24, SQLite had 401,852 of 716,136 tokens and reused all 40,058 captured answers in both phases, with 485,776 retained bytes. Buster had 955,032 of 2,433,563 tokens and reused all 12,743 with 155,200 bytes. Later checkpoints admitted 75,625 SQLite and 91,408 Buster uses. All 16 source/checkpoint combinations matched the ordinary native objects and diagnostics, including the unreached checkpoint. GDB directly compared the complete final resolver events, live names and scope stack, declaration targets and type IDs with the ordinary native compiler on both workloads. All returned exactly the same bytes.

Within the same binary, enabling the consumer reduced median SQLite elapsed time by 3.614 ms in 11 of 18 matched local rounds and user instructions by 681,553 in all 12 counter rounds. Median cycles increased by 33.23 million. On Buster median elapsed fell 9.544 ms in three of six rounds and user instructions increased by 5.34 million. The extra pre-EOF compiler invocation is present in both arms. These local Develop measurements do not establish a Ryzen 7 9700X throughput improvement.

The connected parent already mishandled a late symbol-rename pragma. Both consumers reproduced it in three of 140 source/policy cases. An independently verified sibling repair is in the package. The [source, compilers, full controls and raw native traces](../176935b2a/live-binding-sources.tar.xz) record both experiments and the complete corrected source.
