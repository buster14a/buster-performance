# Compiling arithmetic operands beneath ordinary parents

These sources add `--node-window-constants` to Buster at public base `b86eadcbd3d6c5cdf687f6b67b0281df2ac34034`. It scans a parser postorder chunk for contiguous literal arithmetic, folds qualified unqualified-int operations with Buster's shared transition rules, and keeps the original operator token and checked ICE value on a graph leaf. The parent retains the normal checker, conversions and native lowering. Shapes inspected by shift, division and conditional diagnostics fall back. The option works with debug information. `--time-stages` reports actually admitted roots, removed graph nodes and final graph size. No environment switches enable any part of the measured compiler.

The five-development-revision [source, graph and native oracle](https://github.com/buster14a/buster-performance/tree/e2f9ba0fe31c386801dc8678cb6e7edcf63efc38/docs/measurements/window-compile-2850-2026-11-21/root-splice/pure-interior) compares all surviving checked values, source identities, fallback edges, ordinary conversions and source-tagged native entries on the precursor. Its diagnostic controls corrupt integer payload, ICE or source separately. The current option has an executable regression in the normal checker with full verified values and native source entries on a scoped fixture.

The local qualification uses three independent compilations per test: pristine public base, candidate ordinary driver, and candidate with the new switch. It compares exit status, complete stderr/stdout, and SHA-256 of each complete ELF. The matching-failure rows preserve the behavior on invalid inputs. Tracked file policies include both orders of the pre-existing assignment option and the new constant option. The choice named last controls this comparison. The runtime script also generates deterministic, defined arithmetic and executes each test program under Buster and Clang.

The source code and test fixture are in `source/changes.patch`. The command scripts expect the canonical archived corpus workspaces under `work/`. The pinned Buster source used as an input is distinct from the compiler under test. The SQLite, Lua and musl arguments and all pinned definitions match the [four-corpus recipe](https://github.com/buster14a/buster-performance/tree/56d19310c536d8feea2a7cb120296b77dbf0e052/docs/measurements/window-compile-2850-2026-11-21/1c3dd326d). The independent Ryzen 7940HS samples in `perf/` interleave true single-lane compiles and require an unchanged complete ELF manifest each time. The program verifies the source hash and executable return on the separate runtime grid.
