Fixed stage-report reader

stage_summary.c accepts exactly18 canonical files:
  stages-{base,head}-p{1,2,3}-s{0,64,256}.log
Invoke its frozen executable with the directory holding those files. Other
stages-*.log names are rejected; unrelated results files are ignored. No CSV is
printed until the entire grid passes. Output has nine paired process/placement
rows, ordinary/staged/reference wall medians, check-input/check-expressions
medians and their head/base percentage changes, plus check-declarations,
check-program and the staged span. Stage times are diagnostic elapsed times,
not hardware counters or exact function costs.

This bounded format requires21 measured samples and2 warm-ups, a real reference
executable, all63 unique run/role records, all three summaries, all27 stages,
five preprocessing phases, span/outside/ranking and terminal zero failures.
Summary medians and extrema are checked against the rounded per-run records;
numeric values must be finite and well formed. Relevant checking stages must
be positive, so the reported percentage divisions are defined. Stage shares
and the printed sum receive the tolerance needed by independent rounding.
The sum of stage medians is not equated with the median whole span.

measure_compile.c has no explicit successful object-equivalence marker. Its
terminal `measure-compile: 0 failures` is authoritative because it is printed
after every warm-up/run checks default versus staged objects, every child has
exited0 and every staged report has passed check_clock_read. This reader uses
that contract; it does not invent a marker. The campaign wrapper must also
retain the measure-compile invocation's successful exit status and execution
identity. The reference object's bytes are not compared by measure-compile;
separate source/object correctness checks remain required.

The official-c336 helper build has pre-build source/compiler hashes, exact
NUL-delimited argv and an unchanged-after check in stage-reader-frozen/.
stage-summary-controls.sh replays a historical #914 report as a FORMAT fixture
only, creating the18 labels to test grid handling. It does not assert that
those copies are current measurements. The complete fixture passes and16
damaged variants fail without partial CSV: missing/extra files, duplicate/
missing/wrong run, wrong sample count/median, unknown/duplicate/missing stage,
object failure, absent terminal success, appended error, nonfinite/signed
numeric values and truncation. Source/tool/template identities are frozen
before tests and verified afterward. Real campaign logs need their own fresh
pre-execution identity ledger and post-read unchanged check.

Split diagnostic build

build-probe-split.sh is a separate diagnostic-only alternative to the original
build-probe.sh. prepare copies source, instruments only its probe copy, and
locally preprocesses exact retained checker arguments. Private cpp-output
files keep the original main_unit_checker.c basename. They contain external
system headers: do not publish them or the copied source trees.

Remote codegen retains semantic arguments and uses diagnostic-only -w because
macro expansion loses original diagnostic context. It is accepted only if the
unmodified control object equals retained production8.o byte for byte AND its
complete local-linked image equals the ordinary production executable. Neither
gate may be weakened. Accepted links retain the unchanged production linker
arguments and run through the local cores scheduler. Explicit thread-option
variants failed the whole-image check and were rejected. No stack-protector
policy changes are introduced.

For each variant prepare creates a caller-frozen outer SHA list covering the
inner codegen script, expected input manifest, codegen argv, private cpp bytes
and official compiler. launch-variant.command is the exact remote caller
command: it embeds the expected outer-list SHA as a literal caller argument,
checks that identity and every listed file BEFORE executing the inner script,
then checks them unchanged afterward. Use that exact locally frozen command;
simply running an uploaded unverified launcher would not bind execution.
The inner script also writes its executed argv and compares it to the bound
argv before invoking Clang. Transferred object digests are verified locally
before either exact control gate. Keep remote stdout/status receipts.

Only local PREPARE was smoke-tested under split-format-test using an unused
remote directory name. Its preprocessing and identity checks passed; no remote
codegen, local object generation, link or performance acceptance came from
that generator test. The actual campaign requires independent execution and
both object/image equality gates.
